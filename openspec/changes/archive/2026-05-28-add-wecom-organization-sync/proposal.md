## Why

`aicodex-admin` 后续需要作为统一认证中心和组织数据主数据源，为 `aicodex-api` 统一登录、`aicodex-insight` 下属 AI 用量查看提供稳定的用户、部门和管理范围依据。当前项目已有企业微信登录接入基础，但还没有把企业微信组织架构同步到本地用户/组体系，导致后续权限范围和用户映射缺少可信来源。

## What Changes

- 新增企业微信组织架构同步能力，支持管理员配置企业微信组织同步参数并手动发起全量差异同步。
- 同步企业微信部门树到 `aicodex-admin` 的 Group 体系，并保留企业微信部门 ID、父子关系、主负责人、启用状态等稳定映射信息。
- 同步企业微信成员到 User 体系，并保留企业微信 `userid`、企业 ID、职位、状态，以及当前权限可返回的手机号、邮箱、头像等信息；企业微信未返回敏感资料字段时，不清空已由 OAuth 或人事主数据回填的本地资料。
- 将成员部门、部门负责人、直属上级等核心权限关系拆为独立关系表，避免用文本数组承载后续范围计算。
- 将成员与部门的关系同步到现有用户组关系，确保后台现有用户/组视图可以查看企业微信组织结果。
- 增加同步执行记录，展示执行人、开始/结束时间、结果状态、部门/成员新增更新禁用数量和错误摘要。
- 第一版默认采用“手动全量拉取 + 按稳定 ID 差异更新 + 完整成功后软禁用缺失数据”策略，不清空重建，不物理删除企业微信侧已移除的部门或成员。
- 新增当前用户可管理范围查询能力，为后续数据洞察服务按部门负责人范围和直属/间接下属范围过滤 AI 用量提供统一入口。
- 企业微信通讯录不得同步到系统内置 `built-in` 组织；当管理员以企业微信 Corp ID 配置同步时，系统应基于 Corp ID 绑定或初始化独立业务组织，组织显示名优先采用企业微信根部门/企业显示名。

## Capabilities

### New Capabilities

- `wecom-organization-sync`: 定义企业微信组织同步配置、手动全量差异同步、部门/成员映射、同步结果审计和软禁用规则。
- `organization-management-scope`: 定义基于本地组织树、部门负责人关系和直属上级关系计算当前用户可管理部门、可见成员和下游系统过滤范围的接口能力。

## Impact

- 影响后端对象与服务：`admin/object/group.go`、`admin/object/user.go`、新增企业微信组织同步服务、同步记录模型和 7 张 Xorm 管理表：`wecom_organization_sync_config`、`wecom_organization_sync_run`、`wecom_department_mapping`、`wecom_user_mapping`、`wecom_user_department`、`wecom_department_leader`、`wecom_user_direct_leader`；新增同步表时间字段使用 Go `time.Time` / PostgreSQL `timestamptz` 语义。
- 影响后端接口与路由：新增企业微信组织同步配置、手动执行、执行记录查询、当前用户可管理范围查询接口。
- 影响前端后台页面：新增或扩展企业微信组织同步配置页、同步操作入口、同步结果展示和错误摘要展示。
- 影响认证与数据权限边界：后续 `aicodex-api` 用户映射、`aicodex-insight` 数据范围判断应优先依赖本次同步落地的企业微信稳定标识和管理范围接口。
- 影响内置组织边界：`built-in` 是系统管理组织，`built-in` 下用户会被视为全局管理员；本次变更必须阻止企业微信普通员工落入 `built-in`。
- 需要补充文档与验证：企业微信通讯录权限配置、同步字段映射、首次同步前检查、失败排障、软禁用策略和下游系统对接说明。
