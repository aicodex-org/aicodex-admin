## 背景

认证中心生产交付大概率采用多节点集群部署，企业微信组织架构同步不能只依赖单节点内存定时器，否则会出现节点重启漏跑或多节点同时触发重复同步的问题。

后续还可能接入钉钉、飞书等组织架构同步，当前应沉淀一个通用、默认关闭、集群安全的组织同步调度能力，并先让企业微信全量差异同步接入。

## 变更内容

- 新增通用组织同步调度能力，支持按组织、来源提供方、任务类型配置 cron、时区、启用状态和最近调度信息。
- 新增数据库持久化的调度 fire/lock 记录，通过 `scheduleId + windowStart` 唯一窗口、锁持有者和锁过期时间保证多节点同一时间窗只有一个有效派发者，并允许恢复过期未完成派发。
- 新增组织同步执行器抽象，首个执行器接入企业微信全量差异同步，后续钉钉、飞书可复用同一调度和 fire 去重机制。
- 企业微信同步配置/API/管理页增加定时同步配置项；默认不启用定时同步，管理员显式开启后才生效。
- 企业微信由调度器触发时，运行记录必须使用 `triggerType=scheduled`，actor 使用系统调度身份，现有手动触发仍保持 `triggerType=manual`。
- 保留现有同步运行锁和 stale running 恢复语义，调度 fire 去重只负责“是否触发”，实际执行并发仍由同步 run lease 约束。

## 能力影响

### 新增能力

- `organization-sync-scheduler`: 通用组织架构同步定时调度、集群去重、fire 审计和执行器注册契约。

### 修改能力

- `wecom-organization-sync`: 企业微信组织架构同步从“定时全量同步未来扩展”调整为可配置的定时全量差异同步，并要求 API、配置和运行审计体现 scheduled 触发。

## 影响范围

- 后端对象与表初始化：新增组织同步调度配置表和调度 fire 表，并通过现有 Xorm `Sync2` 路径做 additive schema 初始化。
- 后端服务：新增调度器、执行器注册、DB fire 去重、企业微信执行器适配，以及启动入口。
- 企业微信同步：扩展 run 创建接口以支持 `manual` / `scheduled` trigger，复用现有后台执行和运行锁。
- API 与前端：企业微信同步配置读写增加定时同步字段，管理页提供启用开关、cron、时区和最近触发/结果展示。
- 测试：覆盖默认关闭、多节点同窗口去重、过期 fire 恢复、重复 running 不重复执行、企业微信 scheduled run 审计和配置保存语义。
