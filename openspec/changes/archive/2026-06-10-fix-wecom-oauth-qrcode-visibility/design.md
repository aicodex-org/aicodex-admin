## Context

企业微信 OAuth2 敏感授权主链路使用 Ant Design `QRCode` 渲染授权 URL。该 URL 较长，二维码模块密度高，而底层二维码默认没有静区；登录面板外层存在裁剪样式时，用户容易看到边缘贴边或疑似缺失的二维码。

同一页面的“兼容网页登录”使用企业微信官方组件，官方组件自带更大的码面和明显白边，因此用户反馈中该二维码更清晰。顶部品牌图确实占用垂直空间，但它不是主授权二维码边缘贴边的根因。

## Goals / Non-Goals

**Goals:**

- 让企业微信 OAuth2 主授权二维码完整、清晰、可扫码。
- 不依赖应用是否显示顶部品牌图，二维码自身必须保留静区。
- 保持现有授权 URL、登录意图、轮询、MFA 和 fallback 语义不变。
- 用前端单测固定二维码尺寸、静区和承载区高度。

**Non-Goals:**

- 不调整后端企业微信授权、资料回填或会话完成逻辑。
- 不修改登录品牌图、登录布局全局样式或应用配置。
- 不改变企业微信 PC Web 兼容 fallback 的行为。

## Decisions

- 主授权二维码使用更大的码面并包裹白色静区容器。
  - 原因：这是二维码可识别性的核心要求，能直接对齐企业微信官方组件“更清晰”的视觉特征。
  - 备选方案：缩小顶部品牌图。该方案只能释放纵向空间，不能解决二维码无静区和边缘贴边问题，因此不作为本次主修复。

- 扫码面板最小高度按二维码尺寸和静区计算。
  - 原因：避免将来调整二维码尺寸后忘记同步容器高度。
  - 备选方案：继续使用固定 `240` 高度。该值只略高于旧二维码码面，无法承载新增静区。

- 保持 fallback 组件独立。
  - 原因：fallback 是兼容 PC Web 登录的次要路径，本次线上反馈针对 OAuth2 主授权二维码；修改 fallback 会扩大回归范围。

- 扫码登录模式不展示密码找回入口。
  - 原因：“忘记密码？”属于密码登录表单的恢复路径，企业微信 OAuth2 主路径已经由扫码授权完成身份确认，继续展示该入口会与扫码操作按钮混排，降低当前模式的界面一致性。
  - 备选方案：仅隐藏自动登录复选框。该方案仍保留密码找回链接，无法解决用户反馈的视觉不协调问题。
  - 兼容性：同类微信扫码登录复用相同隐藏规则；密码、验证码、LDAP、WebAuthn 和 Face ID 等非扫码模式保持原有展示逻辑。

## Risks / Trade-offs

- 二维码区域会比原来更高，占用更多登录面板空间。
  - 缓解：只增加到容纳完整二维码和静区所需的最小高度，未改动全局登录品牌图和其他登录方式。

- 隐藏密码找回入口可能减少扫码模式下的备用跳转。
  - 缓解：该入口只在扫码模式隐藏；用户切回密码或验证码登录方式后仍可按原有逻辑找回密码。

- 本地默认应用未配置企业微信 Provider，无法用本地真实登录页直接点击企业微信 tab 验证。
  - 缓解：通过组件测试覆盖主二维码尺寸、静区、状态切换和 fallback 关键分支；在配置了企业微信 Provider 的测试应用上可继续做真实扫码冒烟。
