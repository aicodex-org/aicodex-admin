## Context

前序 change 已经把组织身份四页差异化，并验证 `/organizations`、`/users`、`/roles`、`/permissions` 的列表进入桌面首屏。只读复验确认非组织身份页面仍沿用“页头 + 四指标条 + 入口/风险卡 + 表格”的同质模板，导致 `/providers`、`/applications`、审计运维四页和 `/agents` 的核心列表普遍落在 1000px 以后，移动端甚至需要滚动数千像素才到列表。

本仓库当前是 React 18 + Ant Design + 渐进 TypeScript。既有企业认证中心页面多为 JS/TSX 共存，本 change 只在触碰范围内做局部收敛，不做全仓 TS 迁移、权限模型调整或后端聚合接口扩展。

## Goals / Non-Goals

**Goals:**

- 让非组织身份页面的核心列表或核心操作在 1440x900 桌面首屏内可感知，优先让 table/list top 小于 900。
- 让各业务域有不同的首屏结构：认证源是接入诊断，应用接入是列表优先与缺口核对，审计运维是运行态核对，LLM AI/Gateway 是 AI 入口与网关关系治理。
- 在企业认证中心路由下消除旧英文 Tour 遮罩和本轮触碰范围内的中英文/i18n 债务。
- 移动端压缩页头、指标和入口间距，减少顶部大空白。

**Non-Goals:**

- 不回滚组织身份四页 polish。
- 不新增真实后端统计接口，不把当前列表视图包装成全量治理事实。
- 不触发认证、授权、同步、会话清理、令牌签发、验证码重发或 Gateway projection publish/cleanup/receipt。
- 不修改 `test`、生产/类生产配置、真实密钥、OAuth/OIDC 回调执行或后端认证链路。

## Decisions

### 1. 使用“列表优先 + 紧凑诊断”替代统一工作台模板

认证源、应用接入、审计运维和 LLM AI/Gateway 保留现有数据来源与操作表格，但把顶部信息压缩成一到两层可扫描结构。相比继续增加卡片样式，这能直接解决 table top 过深问题，也避免业务域首屏骨架同质化。

### 2. 保留共享组件但改变域配置和密度参数

共享布局只用于降低重复实现，例如摘要条、状态标签和入口链接；页面自身通过配置决定呈现为诊断条、缺口 rail、运行态核对条或 AI/Gateway 关系条。这样能保持维护成本，同时避免“所有页面看起来一样”。

### 3. 企业认证中心路由默认关闭旧 Tour

旧 `TourConfig.js` 的硬编码英文 Casdoor 文案和遮罩会直接挡住核心列表。相比一次性重写完整 Tour，本轮更保守地在企业认证中心相关路由默认不自动展示旧 Tour，后续如需要新导引再单独用 zh/en 文案设计。

### 4. i18n 在触碰范围内收敛

本轮新增或修改的可见文案全部走 `src/locales/zh/data.json` 和 `src/locales/en/data.json`。旧硬编码中文、英文 fallback 和实现痕迹文案只在触碰组件内清理，避免扩大到无关页面。

## Risks / Trade-offs

- [Risk] 没有后端全量聚合接口，摘要仍只能来自当前列表视图或既有只读数据。→ 文案改为“当前筛选”“只读核对”“配置缺口”等短标签，不宣称全量事实。
- [Risk] legacy BaseListPage 表格和管理壳层本身可能影响移动端宽度或 table top。→ 浏览器复验记录具体坐标；如无法达标，说明是 legacy 表格/数据结构限制而不是隐瞒。
- [Risk] 关闭旧 Tour 会减少首次登录教学。→ 该 Tour 当前是旧 Casdoor 英文导引且遮挡主任务；企业认证中心新导引应单独设计，不在本 change 混入。
- [Risk] 触碰 TSX 组件可能引入测试后缀迁移成本。→ 遵循 `web-admin/AGENTS.md`，触碰对应 TSX 时优先迁移 `.test.tsx`；未触碰的历史债务只记录。
