## Context

当前两个组织同步页已基本使用同一套基础布局。截图反馈的两个问题都来自默认信息过度展示：`序号` 列把低频排障复制入口做成每行常驻图标；定时同步关闭时仍展示 Cron 和时区输入，导致右侧配置列高度高于左侧同步选项列。

## Goals / Non-Goals

**Goals:**

- 序号列默认只显示数字，保持同步记录主表清爽。
- 保留完整运行 ID 的查看和复制能力，排障入口不丢失。
- 定时同步关闭时收起 Cron、时区和最近调度，减少默认空白和视觉重量。
- 企业微信与飞书/Lark 使用一致的基础交互。

**Non-Goals:**

- 不新增正式同步摘要、权限提示搬运或其他填空内容。
- 不修改后端配置模型、同步 run 模型、分页协议或调度语义。
- 不移除飞书 dry-run、绑定诊断、交接资料等已有能力。
- 不进行整页 TS 迁移或共享组件大重构。

## Decisions

1. 序号复制使用点击单元格，而不是常驻 `Typography.Text copyable` 图标。

   原因：复制运行 ID 是低频排障动作，不应该和序号一起成为每行主要视觉元素。点击序号复制能保留能力，同时让列宽和扫读更稳定。

2. hover tooltip 只说明完整运行 ID 和点击复制动作。

   原因：管理员仍能在需要时查看完整 ID；复制反馈通过 `Setting.showMessage` 或项目既有轻量消息完成，不引入新的按钮或图标。

3. 定时同步关闭时折叠高级字段。

   原因：Cron、时区和最近调度只在启用定时同步后才需要编辑或查看。默认收起比新增左侧填充内容更符合 KISS/YAGNI。

4. 保持现有 JS/TSX 文件类型。

   原因：本次是局部展示 polish。企业微信页已是 TSX，飞书页仍是 legacy JS；迁移整页会扩大风险，留给独立 TS 迁移任务。

## Risks / Trade-offs

- 点击序号复制不如常驻图标显性 → tooltip 文案说明“点击复制运行 ID”，测试覆盖复制动作。
- 定时同步关闭时隐藏 Cron/时区 → 已保存值仍保留在 state 和后端配置中，重新启用后显示。
- 测试环境中 AntD Tooltip/消息存在既有 React 18 warning → 聚焦测试验证行为，不把既有测试基础设施迁移混入本任务。
