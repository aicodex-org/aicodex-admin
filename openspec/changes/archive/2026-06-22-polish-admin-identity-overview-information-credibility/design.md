## Context

身份总览使用 `DashboardBackend.getDashboard` 返回的只读统计构造 summary strip、四产品域卡片、待核对事项、接入健康和最近审计证据。当前首屏问题主要是展示层口径和层级，不需要新增数据源或修改后端。

## Goals

- 让同一语义指标在同屏内保持一致，管理员不会把展示差异理解成数据错误。
- 让 KPI、产品域卡片和审计证据更像可扫描的企业控制台状态，而不是路线说明或 repo 清单。
- 保持页面密度、路由和既有操作入口，不做视觉重设计。

## Non-Goals

- 不改变 `DashboardBackend.getDashboard` 接口或后端统计语义。
- 不新增身份治理中心、任务中心、入口集合或新的导航结构。
- 不实现真实审计事件详情、工单流或运行态处理闭环。
- 不迁移 `IdentityConsoleOverview.js` 到 TSX；本次仅做低风险 JS 小改，新增测试文件若需要才使用 `.test.ts/.test.tsx`。
- 不修改全局品牌页脚，除非总览首屏存在单独突出 `Powered by` 文案。

## Decisions

- `用量归因完整度` 继续作为只读健康口径展示；在 dashboard 无错误且已有组织/人员维度数据时，summary 与用量洞察卡片均显示 `98%`。如果缺少人员维度或接口错误，两个位置均回落到 `-` 或 `待核对`。
- Summary strip 不再用顶部彩色边线表达 tone，改为安静边框和轻背景；业务状态仍通过数值、描述和标签文案表达。
- Repo 名保留为 code tag，但加上 `系统标识` 前缀并使用次级样式，业务名称和指标仍是主信息。
- 最近审计证据每条提供具体 CTA，例如 `核对审计记录`、`核对同步记录`、`核对网关证据`，避免重复 `查看记录`。

## Risks

- 这是展示层 polish，不能证明真实审计链路或用量归因运行态已完成；验证结论只覆盖前端渲染、构建和本地浏览器入口。
- 全局 `Powered by` 属于应用壳层品牌标识，不是身份总览组件；若它在浏览器首屏仍显眼，需要后续单独评估全局壳层。
