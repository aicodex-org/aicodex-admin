## Context

`GroupListPage.tsx` 已通过 `fetch({searchedColumn, searchText, type, pagination})` 支持现有后端查询语义，当前列头搜索入口来自 legacy `BaseListPage.js#getColumnSearchProps`。因此本次可以把主查询入口移到页面工具栏，而不改变后端过滤字段、排序、分页或响应结构。

`OrganizationListPage.tsx` 也存在相似列头搜索模式，但组织页列和外层 `OrganizationIdentityCenter` 结构更复杂。本次 P0 先落地群组页和共享查询工具栏组件；组织页对齐作为后续候选，避免把一次 polish 扩成组织账号域全面改版。

## Goals

- 让群组列表的主要查询入口清晰出现在表格上方，管理员不再依赖列头小图标寻找搜索。
- 查询动作、重置动作、更多筛选入口和新增/导入类写操作分组清楚。
- 复用现有 AntD 控件、字体、字号和表格密度，不照搬设计稿的大字号或状态带。
- 以小组件沉淀可复用的查询工具栏结构，但不抽象页面头部、状态带或所有组织账号页面。

## Non-Goals

- 不修改 `GroupBackend.getGroups` 或任何后端接口。
- 不改变群组新增、编辑、删除、导入模板、上传、排序、分页和权限行为。
- 不在本 change 中改造用户、邀请码、组织树、目录质量、认证源或权限角色列表页。
- 不强制组织页同批切换；如果实现中发现组织页复用成本低，也必须保持最小 diff。
- 不新增新的中心、工作台、状态带或设计稿独有字体体系。

## Decisions

- 新增共享 TSX 组件只覆盖“查询工具栏”这一层：字段选择、关键词输入、高频筛选槽、查询/重置/更多筛选和右侧动作槽。
- 群组页默认查询字段为 `name`，可切换到组织、显示名、父级群组和用户字段；类型筛选保留 `Virtual` / `Physical` 语义。
- 查询按钮调用现有 `fetch`，以当前分页为基础回到第一页；重置清空工具栏状态并按现有分页重新加载，不新增 URL 状态或后端字段。
- 更多筛选默认折叠，仅展示后续扩展容器，不在默认首屏压低表格。
- 列头继续保留排序；群组页不再为可搜索文本列注入 `getColumnSearchProps`，以避免列头搜索图标继续成为主入口。

## Risks

- 本次只完成群组页；组织页仍可能保留列头搜索入口。该差异会在最终报告中作为后续候选，而不作为本次 blocker。
- 查询工具栏仍复用现有后端单字段查询语义，不能实现多字段同时搜索或复杂组合查询；UI 文案和组件设计需避免暗示新增了高级后端过滤能力。
