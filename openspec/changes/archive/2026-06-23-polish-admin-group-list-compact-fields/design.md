## Context

`GroupListPage.tsx` 已经迁移到 `.tsx`，并在上一版 change 中接入了企业查询工具栏、内联更多筛选、长字段截断和轻量操作按钮。当前剩余问题不是单个字段样式，而是默认表格列仍过多：组织技术 ID、创建时间、显示名称和完整用户 chip 都占用默认横向宽度，使列表更像数据导出表而不是后台管理列表。

本 change 是上一版视觉密度的窄范围增量：只调整 `/groups` 默认表格信息架构和桌面滚动策略，不改变后端请求、过滤、排序或写操作契约。

## Goals / Non-Goals

**Goals:**

- 将群组默认表格收敛到管理员扫描和操作必需字段。
- 用“群组主文本 + 弱副 ID”承载名称、显示名和技术 ID，不再拆成多列。
- 用用户数量替代完整用户 chip 列表，降低横向宽度和视觉抢占。
- 在桌面端去掉横向滚动轴；窄屏仍通过表格内部滚动兜底。
- 补充聚焦测试，先证明旧 9 列/横滚行为不符合新目标，再实现。

**Non-Goals:**

- 不实现新的详情抽屉或详情页。
- 不新增后端字段、接口、查询参数或权限判断。
- 不移除已有编辑、删除、上传、下载模板、类型筛选和高级筛选能力。
- 不把其它组织账号列表页同步改成相同列结构。

## Decisions

- 默认列保留 5 列：`群组`、`上级组`、`用户`、`更新时间`、`操作`。理由：这组字段覆盖识别、层级、规模、最近变化和操作路径；类型字段混合了本地组规则和外部目录来源语义，默认展示容易误导，多租户外部同步场景下更适合作为筛选和详情级信息。
- 群组列用两行结构：第一行优先展示 `displayName || name`，第二行展示技术 `name` 并提供复制入口。替代方案是只展示显示名，但会降低排障和导入数据对照效率。
- 用户列展示数量。替代方案是保留首个用户 + `+N`，但用户 ID 对群组扫描不是主任务，且仍会造成 chip 噪声。
- 类型筛选继续保留在工具栏，后端 `field=type` 查询语义不变。替代方案是在默认列显示 `类型`，但当前 `Virtual`、`Physical`、`group:wecom-department` 并不是同一层分类，后续企业微信、飞书等多来源同步会进一步放大歧义。
- 桌面端 `Table` 不再配置 `scroll.x`，并取消固定左右列；通过 `tableLayout="fixed"`、百分比列宽和单元格截断保证容器内展示。移动端可以继续配置最小宽度滚动，避免极窄屏压坏操作列。
- 群组列表初始 `pageSize` 调整为 20。理由：字段收敛后单行高度和横向负担下降，20 行更接近已确认的桌面密度，也能减少默认 10 行造成的底部空白；共享分页组件默认值保持不变。
- 继续复用当前工具栏和 AntD Table，不新增表格库或全局主题改动。

## Risks / Trade-offs

- [组织 ID 和创建时间默认不可见] → 群组技术 ID 仍可复制，完整对象信息保留在详情/编辑路径；本 change 不删除数据。
- [用户数量不展示具体成员] → 用户列成为规模线索；具体用户通过详情或后续 hover/抽屉承载，避免默认表格噪声。
- [无横滚可能压缩列宽] → 桌面使用比例列宽和文本截断；移动端保留滚动兜底。
- [测试过度绑定 DOM] → 聚焦测试断言列 key、滚动配置和核心渲染语义，不依赖像素值。
