## Context

`/organizations` 当前通过 `OrganizationIdentityCenter` 包裹 `OrganizationListPage` 表格。该容器为组织、用户、角色、权限四类实体提供差异化工作台顶部，其中组织页使用目录健康/边界面板骨架。

用户反馈集中在组织页：它实际是组织对象列表，不应呈现为“组织主数据工作台”或首页式诊断区域。上一版 health strip 已经压缩了四卡片，但仍保留独立标题、描述和健康状态条，红框区域仍然过大。

## Goals / Non-Goals

**Goals:**

- 让 `/organizations` 首屏以组织列表为主任务，顶部只保留列表标题、结果数、添加入口、筛选工具栏和弱健康上下文。
- 将 `组织主数据工作台` 改为对象名 `组织`，并与左侧导航、tab 文案保持一致。
- 将目录健康、同步来源、边界信息降级为工具栏右侧辅助文本，并提供 `目录质量` 入口。
- 将 `密码类型` 过滤入口从表头下拉统一到查询字段和更多筛选中，避免同一查询区域外另有隐藏筛选入口。
- 保持组织列表查询、更多筛选、分页、排序和写操作语义不变。

**Non-Goals:**

- 不改 `/users`、`/roles`、`/permissions` 的工作台顶部骨架。
- 不改侧栏、标签页关闭、父子菜单选中态或组织账号 IA。
- 不新增目录健康 API、不触发刷新状态、同步执行、授权刷新或 Gateway projection。
- 不重做组织目录质量页面本体。

## Decisions

1. **组织页从通用工作台顶部中分流。**
   `OrganizationIdentityCenter` 继续承载四类实体页，但 `page === "organizations"` 时渲染紧凑列表顶部；其它页面沿用现有工作台，降低写集和回归范围。

2. **列表标题与工具栏合并为首屏主区域。**
   组织页首行显示 `组织`、`N 条结果` 和 `添加`，第二行放现有 `EnterpriseListQueryToolbar`。这比“标题区 + health strip + list section”少一个页面层级，能直接把表格上移。

3. **健康信息只作为辅助上下文。**
   目录健康文案展示为 `目录健康：3 项待关注 · 同步来源：企业微信/飞书 · 边界：全部`，右侧只保留 `目录质量` 轻量入口。`刷新状态` 不在组织列表页出现，避免把诊断动作提升为主页面动作。

4. **添加入口仍由组织列表页提供。**
   `OrganizationListPage` 当前把 `添加` 放入共享查询工具栏 action。实施时将组织页的 `添加` action 上移到紧凑列表顶部，同时保持管理员权限禁用判断和原 `addOrganization` 调用。

5. **更多筛选沿用已有内联展开。**
   本 change 不改变更多筛选的字段、AND 过滤、分页 total 或重置语义，只调整它在紧凑顶部结构中的位置和视觉层级。

6. **密码类型过滤统一到列表查询。**
   组织列表不再通过表头 filter 处理 `passwordType`；主查询字段可选择 `密码类型` 并切换为密码类型 Select，更多筛选中也使用同一组选项。选项与组织编辑页保持一致，包含 `bcrypt` 等当前默认值。

## Risks / Trade-offs

- **组织页特化渲染增加 `OrganizationIdentityCenter` 条件分支。** → 只对 `page === "organizations"` 分支加专用布局，并用测试锁定其它实体页仍保留各自工作台文案。
- **添加按钮从工具栏动作区移到标题行可能影响现有测试。** → 更新聚焦测试，断言管理员可点击、非管理员禁用，以及查询工具栏不再混入写操作。
- **健康上下文来自现有静态 profile，不是真实后端诊断。** → 文案保持只读、当前视图口径，不声称后端全量治理事实。
- **桌面窄宽下右侧健康文本可能挤压筛选。** → 样式采用响应式换行/截断，移动或窄屏时健康上下文落到工具栏下方。
- **密码类型从表头 filter 迁移可能改变管理员习惯。** → 查询工具栏和更多筛选均暴露 `密码类型`，并保留现有后端 `field=passwordType&value=...` 查询契约。

## Migration Plan

- 前端以一个工作分支交付，默认 release-candidate-only。
- 修改完成后运行 OpenSpec validate、聚焦 Jest、TypeScript gate/typecheck、build 和本地浏览器截图。
- 若用户验收通过，再按后续授权执行 archive/closeout；本轮 RC 不合入 `hfl-test-base`、不 push `test`。
