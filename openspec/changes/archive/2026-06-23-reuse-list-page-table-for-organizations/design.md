## Context

群组列表已经沉淀出两个可复用边界：`EnterpriseListQueryToolbar` 负责列表查询区布局和动作分组，`ListPageTable` 负责表格密度、边框、排序提示和固定布局等共同属性。组织列表仍直接使用 Ant Design `Table`，默认列包含 Salt、头像、余额、额度和币种等低频详情字段，并把 `添加` 放在 `OrganizationIdentityCenter` 的顶部 action 中，和群组列表已验收模式不一致。

组织页同时有自己的目录健康上下文、高级筛选字段、密码类型查询和组织/用户跳转，这些属于页面语义，不应为了复用而硬统一。

## Goals / Non-Goals

**Goals:**

- 让组织列表复用共享表格壳和查询工具栏动作区，降低后续用户、应用接入等相似列表页改造成本。
- 默认隐藏组织列表中的低频详情列，让列表聚焦组织识别、访问、密码策略、软删除状态和操作。
- 桌面端让组织表格内部滚动，保持标签页、查询工具栏和目录健康上下文稳定。
- 保持组织页现有查询、排序、分页、添加、编辑、删除、群组/用户跳转和目录质量入口语义。

**Non-Goals:**

- 不改造后端 `OrganizationBackend` API 或排序/过滤契约。
- 不新增列配置管理、用户自定义列、远端可排序字段元数据或高级筛选后端查询能力。
- 不同时改造用户、应用接入等其它列表页。
- 不触发组织同步、目录修复、Gateway projection publish 或外部系统调用。

## Decisions

1. 组织列表使用 `ListPageTable`，而不是复制群组页表格 CSS。

   这样组织页自动继承统一表格类名、密度、边框、排序 tooltip 和 fixed layout。页面只保留自己的列定义、row key、scroll 和 title 内容。

2. `添加` 通过 `EnterpriseListQueryToolbar.actions` 展示。

   群组页已经把写操作从查询按钮组里分离到工具栏 action 区。组织页沿用同一入口，同时继续用 `Setting.isAdminUser` 控制非管理员不可添加。

3. 默认列只保留组织列表主任务所需字段。

   `passwordSalt`、`defaultAvatar`、`orgBalance`、`userBalance`、`balanceCredit` 和 `balanceCurrency` 从默认表格列移出。它们仍可在详情页或后续字段配置方案中处理，本 change 不删除数据模型字段。

4. 桌面端使用表格内部纵向滚动，移动端保留横向滚动兜底。

   组织列表删列后桌面端不应依赖横向滚动轴才能看到操作列；移动端空间不足时仍允许表格内部横向滚动，避免列内容挤压到不可读。

5. 高级筛选字段保持组织页自己的字段源。

   复用只覆盖布局和共同属性，不把群组页字段、类型筛选或用户列行为强加给组织页。

## Risks / Trade-offs

- [Risk] 隐藏低频列后，少数管理员需要从列表快速查看余额或头像时路径变长。
  Mitigation: 本 change 仅隐藏默认列表列，不删除数据；后续如有真实高频需求，可通过详情页、列配置或专门财务视图补齐。

- [Risk] 桌面端固定 `scroll.y` 可能在极小高度窗口里让表格数据区偏短。
  Mitigation: 采用与群组列表一致的 `calc(100vh - 360px)` 基线；移动端仍使用横向滚动兜底。

- [Risk] 共享组件过早抽象可能限制页面差异。
  Mitigation: 共享组件只负责表格壳和工具栏布局，查询字段、业务上下文、操作按钮和后端契约仍由页面自己决定。
