## Context

群组列表的改善来自一组组合动作：把主对象信息合并到可扫描主列、技术 ID 降权并弱复制、用户字段数量化、行操作轻量化、桌面端取消横向滚动依赖、分页默认 20 条。组织页上一轮只复用了 `ListPageTable` 和 `EnterpriseListQueryToolbar`，但仍保留多列后端字段、独立 favicon 列、重按钮操作和挤在搜索行右侧的目录健康上下文，因此视觉上仍不像同一套列表系统。

本 change 的设计目标是修正复用粒度：公共组件必须承载已验证的列表信息结构和交互降噪，而不是只包 Ant Design `Table`。

## Goals / Non-Goals

**Goals:**

- 让组织页默认列表视觉密度接近群组页，消除表头换行、横向滚动感和重操作按钮噪声。
- 把组织名称、favicon、技术 ID 和复制入口整合为主识别单元。
- 把主页地址、同步来源等长文本降权为截断信息，不撑高行。
- 把行操作改成轻量动作组，保留群组、用户、编辑、删除既有行为。
- 把目录健康上下文移出搜索行主控件区。
- 沉淀可复用的主识别单元、弱复制按钮和轻量行操作组，后续用户、应用接入等页面复用时先复用信息结构。

**Non-Goals:**

- 不改组织列表后端 API、排序、分页或高级筛选契约。
- 不新增列配置中心、远端可排序字段元数据或表格 schema 配置系统。
- 不同时改造用户、应用接入、用量接入等其它列表页。
- 不触发组织同步、目录修复、Gateway projection publish 或外部系统调用。

## Decisions

1. 组织页默认列改为“对象识别 + 少量状态/策略 + 操作”。

   组织列承担显示名、组织名/技术 ID、favicon 和复制入口；主页地址归入低权重摘要列；密码类型、软删除、创建时间保留为扫描字段；操作列只展示轻量动作。这样避免把后端字段一列一列铺开。

2. 抽取 `ListPageIdentityCell` 和 `ListPageRowActions` 这类窄边界组件。

   组件只表达通用列表交互：主文本、次文本、图标/头像、弱复制、轻量动作布局。它们不理解组织目录健康、群组类型或应用接入状态，避免业务语义被公共组件写死。

3. 弱复制入口默认低可见度。

   复制技术 ID 是必要能力，但不能像主字段一样抢眼。复制按钮默认轻色，hover/focus 时增强；长 ID 使用截断和 tooltip。

4. 目录健康上下文使用工具栏辅助槽位。

   搜索主控件组只放字段选择、关键词、查询、重置、更多筛选和 actions。目录健康、同步来源、边界和目录质量入口放到低权重上下文区域；组织页桌面端使用工具栏右侧辅助槽位，小屏再回落换行，避免挤压查询控件或贴近表头。

5. 默认分页 20 条/页。

   群组页已采用 20 条/页减少桌面空白，组织页同步采用同一默认值；不改变用户手动分页选择语义。

6. 列表页字号和布局使用语义化 token。

   标题、查询控件、表头、单元格、次级文本、行操作、panel padding、工具栏间距、表格 title padding、查询控件宽度、右侧辅助区宽度和表格滚动条分别使用 `--list-page-*` 变量。`ListPageTable` 自动把 `title` 内容包进共享工具栏 shell，后续用户、应用接入等列表复用时先复用这些语义 token 和公共 table shell，避免页面各自写死字号或间距导致组织页和群组页层级不一致。

## Risks / Trade-offs

- [Risk] 主页地址、favicon 从独立列降权后，少数管理员需要横向比较这些字段时效率下降。
  Mitigation: 信息仍在主识别/摘要单元中可见或可达；后续如有强需求，再引入列配置，而不是回到默认多列铺满。

- [Risk] 抽取公共组件可能再次被误用成“套壳”。
  Mitigation: 组件注释写明复用的是已验证的信息结构和交互模式；OpenSpec tasks 要求组织页测试覆盖具体视觉行为，不只断言组件类型。

- [Risk] 操作列轻量化后，群组/用户跳转的主行动感下降。
  Mitigation: 保留文字标签和既有路由；这些是行级导航，不应长期以多个主按钮抢占数据焦点。
