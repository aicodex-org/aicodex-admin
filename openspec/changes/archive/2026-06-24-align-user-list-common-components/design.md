## Context

组织、群组列表已经沉淀 `ListPageTable`、`EnterpriseListQueryToolbar`、`ListPageIdentityCell` 和 `ListPageRowActions`，用于统一列表页表格密度、查询工具栏、主识别单元和轻量行操作。用户列表当前已复用表格壳和查询工具栏，但用户识别列与行操作仍在页面内手写 JSX，导致后续调整主对象字号、弱复制入口、辅助文本层级或行操作间距时仍需要逐页改动。

本次 change 只收用户列表的公共组件复用缺口，不改变用户列表列语义、查询契约、分页、排序、上传、下载模板、删除、移出群组或模拟登录行为。

## Goals / Non-Goals

**Goals:**

- 用户列表主识别列复用 `ListPageIdentityCell`，与组织、群组列表共享主文本、辅助文本、弱复制入口和可选图标的组件边界。
- 用户列表行操作复用 `ListPageRowActions`，与组织、群组列表共享低噪声行操作布局。
- 增加聚焦测试，防止用户列表再次退回页面内手写主识别和行操作布局。

**Non-Goals:**

- 不调整用户列表默认字段范围、查询字段、高级筛选字段或后端查询语义。
- 不新增后端 API，不改变认证、授权、组织同步、Gateway projection 或外部系统执行链路。
- 不同批改造应用接入、身份来源或其他列表页面。

## Decisions

- 复用现有公共组件而不是新增用户专属封装。原因是组织、群组、用户三类列表已经共享同一套 `enterprise-list-*` 样式语义；继续引入用户页专属壳会把统一调参入口重新拆散。
- 保留用户页的列定义和业务动作，只替换渲染边界。原因是本次目标是公共组件复用，不是重做用户列表业务行为；编辑、删除、移出群组、模拟登录等按钮的禁用条件和回调必须继续由用户页控制。
- 使用测试断言公共组件边界和关键 DOM 语义。原因是截图能发现视觉不一致，但无法防止后续代码再次绕开公共组件；测试应覆盖主识别公共类名、复制入口和行操作公共类名。

## Risks / Trade-offs

- 用户头像字段质量不一致可能导致视觉兜底仍依赖现有头像处理。缓解：只保持现有头像/占位策略，不在本 change 中引入新头像加载逻辑。
- 公共组件测试如果过度绑定 DOM 结构会阻碍后续重构。缓解：测试只断言公共语义类名、可见业务动作和既有交互，不绑定 AntD 内部结构。
- 用户页仍有页面专属列与筛选配置。缓解：本 change 明确保留页面专属配置；后续列表继续复用时再逐步沉淀更稳定的配置层。

## Migration Plan

1. 先补用户列表测试，确认当前代码未满足公共主识别和行操作边界。
2. 将用户识别列和行操作替换为公共组件，保留原业务 props 与回调。
3. 运行聚焦测试、TypeScript 检查、构建和 OpenSpec 校验。

回滚策略：还原用户列表渲染替换和对应测试即可，不涉及数据迁移或接口变更。
