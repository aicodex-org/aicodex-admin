## Context

用户页当前由 `UserListPage.tsx` 渲染，仍使用 AntD `Table` 直接配置大量字段，并通过列头搜索图标承担主要查询入口。表格默认列包含组织、应用、技术用户名、头像、联系方式、真实姓名、验证状态、地区、类型、标签、注册信息、余额、管理员/禁用/删除状态和操作，导致桌面端必须横向滚动才能完成扫描。群组页已使用 `ListPageTable`、`EnterpriseListQueryToolbar`、主识别列和轻量行操作完成收敛，组织页也已沿用同类模式。

## Goals / Non-Goals

**Goals:**

- 让 `/users` 首屏更像可操作的账号列表，而不是后端字段导出表。
- 默认列聚焦显示名称/用户名、来源归属、联系方式、验证状态、更新时间和操作。
- 桌面端尽量消除默认横向滚动轴，并让操作列在可见区域内稳定可达。
- 保留上传、下载模板、新增、编辑、删除、移出群组、模拟登录、排序、分页和现有后端查询语义。
- 头像加载失败时使用稳定兜底，不展示破图图标。

**Non-Goals:**

- 不改用户详情页、密码、余额、管理员、禁用、删除等字段的数据模型或编辑能力。
- 不新增用户列表后端 API，不改变 `UserBackend` 查询、删除、上传或模拟登录契约。
- 不把群组页字段或组织页目录健康上下文硬编码到用户页。
- 不处理侧栏、标签栏、组织页或群组页的其它视觉问题。

## Decisions

1. **默认列收敛为主识别列 + 少量业务列。**
   用户主列合并头像、显示名称、技术用户名和必要的组织/应用次级文本；联系方式列合并邮箱与手机号；验证状态用标签表达；更新时间优先使用既有 `createdTime` 作为当前可用的生命周期时间信号。这样可以消除多列技术 ID 对扫描的干扰，同时不删除底层字段。

2. **复用共享表格壳和工具栏，但不强行统一查询字段。**
   `UserListPage` 改用 `ListPageTable` 承载统一密度、固定布局和排序 tooltip 行为；查询工具栏复用 `EnterpriseListQueryToolbar`，字段集合按用户页业务定义，继续传递现有 `searchedColumn` / `searchText` / pagination / sort 参数。

3. **用户页更多筛选仍映射到单字段查询。**
   `EnterpriseListQueryToolbar` 已提供 `advancedFilters` 插槽，用户页接入该公共能力。由于用户列表后端契约仍是单字段 `field + value` 且存在服务端分页，用户页更多筛选输入任一字段时同步主查询字段和值，并清空其它高级输入；不在当前页数据上做多字段 AND 过滤，避免结果数和分页产生误导。

4. **列表文本层级使用共享样式语义。**
   组织、群组、用户列表共同使用 `enterprise-list-primary-text`、`enterprise-list-secondary-text`、`enterprise-list-inline-link`、`enterprise-list-status-tag`、`enterprise-list-row-actions` 等 class 表达主文本、辅助文本、链接、状态和操作密度。页面保留原专属 class 负责局部布局，避免一次性重构过宽。

5. **行操作降权而不是删除能力。**
   模拟登录属于高风险但既有能力，保留为轻量按钮；编辑为普通链接按钮；删除/移出群组保留确认和禁用条件，但视觉权重低于数据本身。

6. **头像兜底放在前端展示层。**
   对头像空值或加载失败显示首字/默认头像样式，不改变记录里的 `avatar` 字段，也不阻断点击详情。

## Risks / Trade-offs

- 默认隐藏低频列可能让少数管理员少一步看到注册来源、余额或开关状态。缓解：这些字段仍保留在详情页、数据模型和可查询契约中；本 change 只收敛默认表格。
- `createdTime` 不是严格更新时间。缓解：当前用户记录模型未稳定提供 `updatedTime`，本 change 使用现有生命周期时间字段并在文案上保持为“创建时间/时间”而非伪造更新时间。
- 查询工具栏接入会改变测试结构。缓解：补充聚焦 Jest 覆盖查询参数、默认列、行操作和上传/下载语义。
