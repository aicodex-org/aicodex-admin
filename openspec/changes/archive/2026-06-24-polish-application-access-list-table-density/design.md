## Context

应用接入分组下的 `资源`、`证书`、`密钥`、`Webhook 回调`、`Webhook 事件` 都是对象列表页，但当前仍主要继承旧 `BaseListPage` 表格结构：标题塞在 Table title 中、列内搜索入口分散、固定操作列和横向滚动较重。与此同时，`组织`、`群组`、`用户` 和 `应用` 列表已经沉淀了 `ListPageTable` 与 `EnterpriseListQueryToolbar`，用户正在要求这些后台对象列表形成一致的信息密度和筛选体验。

这些页面仍承载既有写入和运行态操作：资源上传/删除/复制链接，证书下载/删除，密钥新增/删除，Webhook 新增/删除，Webhook 事件状态筛选、详情抽屉和重放。因此本次设计只对列表外壳、列展示和搜索入口做兼容性 polish，不改变后端查询契约或业务动作。

## Goals / Non-Goals

**Goals:**

- 五个目标页面使用统一的列表标题、结果计数、主搜索、重置和“更多筛选”入口。
- 页面继续通过既有 `field`、`value`、分页和排序参数调用后端，不新增多字段查询 API。
- 表格密度、排序 tooltip、固定列视觉、长文本截断和操作按钮权重对齐到已采用的公共列表体验。
- 增加聚焦测试，覆盖统一列表壳、主搜索、扩展搜索映射和关键业务操作保留。
- 若目标页已经是 TSX，记录无需 JS 到 TS 迁移；不做无关 JS 文件迁移。

**Non-Goals:**

- 不改后端接口、权限、路由、数据模型、认证/OAuth/OIDC 回调、Gateway projection 或真实运行态同步。
- 不把扩展搜索实现为前端当前页多字段过滤，因为这会改变分页总数和后端查询语义。
- 不重构 `BaseListPage` 的整体架构，不迁移所有 legacy list page。
- 不隐藏或删除既有用户可用操作；只调整展示密度、入口位置和按钮权重。

## Decisions

1. **继续复用 `EnterpriseListQueryToolbar` 和 `ListPageTable`，不新建第二套应用接入列表组件。**
   - 原因：组织、群组、用户、应用页面已经采用这一套结构，用户明确希望其它表格参考群组页经验。
   - 替代方案：为应用访问对象单独做 `ApplicationAccessListToolbar`。该方案会让不同对象列表继续分叉，后续维护成本更高。

2. **页面级状态维护 `queryField`、`queryKeyword` 和 `advancedQueryKeywords`，搜索时映射回既有单字段查询参数。**
   - 原因：现有后端接口均接收单个 `field + value`，保持这一路径可以保留分页、排序、总数和后端权限语义。
   - 替代方案：一次性提交多个 advanced 字段。当前后端没有对应契约，会让 UI 表现超过真实能力。

3. **扩展搜索采用“单次生效一个非空高级字段”的保守策略。**
   - 原因：在不改后端前提下，可提供更清晰的字段入口，同时避免多字段同时输入却只生效部分字段的隐性误导；若用户填入多个高级字段，页面应采用稳定顺序选择第一个非空字段或在实现中禁用冲突。
   - 替代方案：本地过滤当前页数据。该方案会破坏服务端分页和总数认知，因此不采用。

4. **列展示以“关键识别 + 状态/时间 + 操作”为主，技术细节通过截断、Tooltip 或扩展筛选承接。**
   - 原因：本次目标是降低横向滚动和视觉噪声，同时不移除业务能力。敏感或低频字段不得被放大展示。
   - 替代方案：保留所有历史列并仅替换表格壳。该方案不能解决横向滚动和扫描压力。

## Risks / Trade-offs

- [Risk] 目标页面仍继承 `BaseListPage`，状态类型较宽，直接强类型化过深可能引入行为回归。 → Mitigation：仅为新增状态和渲染辅助函数加局部类型，保留既有 fetch/action 实现的调用方式。
- [Risk] 统一搜索可能与旧列内搜索测试或用户习惯不完全一致。 → Mitigation：保留原后端 `field/value` 语义，并用测试验证主搜索和更多筛选都会传入正确字段。
- [Risk] 减少表格横向滚动可能导致某些技术字段不再首屏可见。 → Mitigation：只降权低频或过长字段，关键对象名、归属、状态、时间和操作保留；必要长文本用 Tooltip/复制动作承接。
- [Risk] Webhook 事件页有重放和详情抽屉，样式改造可能影响操作入口。 → Mitigation：先补失败测试覆盖重放/详情保留，再改表格外壳。

## Migration Plan

1. 在当前工作分支内创建并验证 OpenSpec artifacts。
2. 先补 Jest 失败测试，覆盖五个页面的共享列表壳、查询工具栏、更多筛选和关键操作。
3. 逐页替换表格外壳和搜索入口，保持现有 fetch 参数和 action 方法。
4. 运行聚焦测试、`yarn typecheck --pretty false`、`git diff --check`，可行时启动本地预览进行浏览器检查。
5. archive 前记录验证证据；若目标页均已是 TSX，在验证记录中说明本次无 JS 页面迁移。
