## Context

近期治理列表页已经沉淀了 `ListPageTable`、`LegacyListPageToolbar` 和 `ListPageRowActions` 等公共壳。审计运维四个页面仍是旧 `BaseListPage` 表格：表头里带列搜索，按钮和行操作不统一；上方审计运维摘要与左侧菜单、顶部 tab、列表标题重复，占用首屏空间，导致列表任务被压低。

## Goals / Non-Goals

**Goals:**
- 移除四个分页列表顶部重复摘要块，使列表更早进入首屏。
- 四个分页列表复用统一列表治理壳的查询、更多筛选、按钮、操作列和分页样式。
- 保持现有搜索字段、排序字段、分页和删除/详情/新增行为兼容。
- 不调整公共列表壳已经调好的全局样式变量。

**Non-Goals:**
- 不重做审计运维的信息架构和菜单。
- 不改后端接口，不新增批量处理、真实风险队列或新的审计核对动作。
- 不迁移这四个旧页面到完整 TypeScript，除非局部类型测试需要。
- 不调整其它列表页面的样式。

## Decisions

1. **四个分页列表不再渲染审计运维摘要块，不改公共壳全局样式。**
   摘要中的入口、数量和风险提示与左侧菜单、顶部 tab、列表标题和表格数据重复，收益低于首屏空间成本。实现上从四个列表页移除摘要渲染，而不是改 `LegacyListPageToolbar`、`ListPageTable` 或全局 `--list-page-*` 变量，避免影响组织、群组、资源、证书、密钥、Webhook 等已调好的页面。

2. **旧 `BaseListPage` 页面通过 `LegacyListPageToolbar` 接入统一搜索。**
   这些页面后端仍使用 `searchedColumn/searchText` 单字段查询；`LegacyListPageToolbar` 已明确保留该契约。四个页面只提供字段配置，不新增多字段后端语义，更多筛选仍按单字段搜索处理。

3. **表格列移除 `getColumnSearchProps`，保留 sorter。**
   查询入口统一上移到工具栏和更多筛选，减少表头图标噪声；排序仍沿用既有 `sorter: true` 和 `handleTableChange` 参数。

4. **行操作使用 `ListPageRowActions`，Token 新增按钮放入 toolbar actions。**
   令牌页表格 title 里的新增按钮移到统一标题右侧；详情/编辑/删除使用统一低噪声行操作按钮。

5. **审计运维列表自行收敛列宽和敏感长字段。**
   四个页面不再使用 `scroll={{x: "max-content"}}`；令牌授权码、访问令牌和验证码不进入列表列，避免横向滚动和敏感值在表格中抢占视觉。相关字段仍保留在页面搜索字段中，详情/编辑流程沿用既有页面。

6. **表格 body 滚动高度对齐组织等统一列表页。**
   审计运维四页使用页面级 `scroll.y`，默认 `calc(100vh - 360px)`，展开更多筛选后为 `calc(100vh - 414px)`。这样默认 20 条/页时保持列表标题、查询工具栏和表头稳定，滚动只发生在表格数据区。

7. **操作日志详情抽屉保留右侧查看，但内部接管滚动。**
   全局 Drawer body 目前为了其它页面使用场景设置了 `overflow: hidden`，操作日志详情内容较多时不能依赖 Drawer body 自身滚动。本次只在操作日志详情内部增加 `audit-record-detail-content` 滚动容器，并把摘要、技术请求、脱敏响应和脱敏对象载荷分层展示；视觉上压低卡片感，使用扁平分区和轻边界。脱敏响应通常较短，保留较小代码区；脱敏对象载荷更长，取消固定高度并跟随抽屉主滚动，避免双滚动。

8. **代码区复制按钮只复制脱敏展示值。**
   脱敏响应和脱敏对象载荷分区右侧提供低噪声复制按钮，使用既有 `general:Copy`、`general:Copied to clipboard successfully` 和 `general:Failed to copy` 文案。复制内容来自 `sanitizeAuditDetailValue(...)` 后的展示值，不复制原始敏感字段；反馈以内联图标和 tooltip 表达，不触发全局静态 message。

9. **Editor 过滤内部布局和主题 props 后再传给 CodeMirror。**
   操作日志详情抽屉复用 `Editor` 展示脱敏内容；`fillWidth`、`fillHeight`、`dark` 等是项目内部约定，不应继续透传到 DOM。实现上只在 `Editor` 内部解构这些 props，保留原有宽高、主题、语言扩展和 `onChange` 行为。

10. **登录会话列表折叠 Session ID，并明确操作范围。**
    `session` 表的一行表示 `组织 / 用户 / 应用` 下的一组 `sessionId`。列表默认展示前 2 个 ID，超过部分用“+N 更多”打开右侧抽屉查看，避免历史残留 ID 把行高撑开。单个 ID 的关闭操作表达为“踢出该会话”；行操作表达为“删除该应用下全部会话”，避免误解成删除用户的所有组织/应用会话。当前后端会设置服务端 session 与业务 `ExpireTime`，但 `sessionId[]` 索引表没有定期清理过期 ID，本次只做前端展示和操作语义收敛，过期索引清理留作后端治理。

## Risks / Trade-offs

- **旧页面仍是 JS class 组件** → 本次保持最小迁移，避免把视觉统一和 TS 全量迁移混在一起；通过聚焦测试和 typecheck/build 覆盖风险。
- **更多筛选视觉上像多字段，但后端仍是单字段搜索** → 复用 `LegacyListPageToolbar` 的既有说明和实现，输入一个扩展字段时清空其它字段。
- **移除摘要减少总览感** → 当前域由左侧菜单、顶部 tab 和列表标题表达；可见总数由统一列表工具栏表达；四类入口由菜单和工作页 tab 承接。
- **桌面和窄屏布局风险** → 通过本地前端连接 60 后台做浏览器目视验证；本次保证 1440px 桌面验证下无横向滚动且表头固定，窄屏仍按现有移动端表格行为处理。
- **详情抽屉内容长度不稳定** → 通过专用滚动容器和默认展开的折叠面板保证首屏可扫描；对象载荷交给主滚动承载，极大对象后续可再单独评估全屏查看。
