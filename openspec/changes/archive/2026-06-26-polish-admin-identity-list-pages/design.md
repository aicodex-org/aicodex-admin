## Context

本次变更是在既有统一列表壳已经覆盖组织、群组、用户、应用接入对象和权限/Casbin 列表的基础上做收口。用户反馈角色、权限页面顶部区域主要是跳转入口，左侧菜单已经覆盖这些入口；模型、适配器、执行器等表格的固定列分割线也会造成额外视觉噪声。

## Goals / Non-Goals

**Goals:**

- 让 `/roles`、`/permissions` 以列表、搜索和行操作作为首屏主任务。
- 移除角色/权限独立顶部工作台，避免重复导航和无效信息块。
- 在 `/roles`、`/permissions`、`/models`、`/adapters`、`/enforcers` 桌面列宽可容纳时取消不必要固定列。
- 保持既有路由、后端契约、权限、CRUD、排序、分页和搜索行为不变。

**Non-Goals:**

- 不重新设计组织、群组、用户列表。
- 不新增后端聚合接口或全量治理统计。
- 不改变 Casbin 模型、适配器、执行器的数据模型和写入语义。
- 不处理已有 React 18 `ReactDOM.render` 或个别组件生命周期 warning。

## Decisions

- 直接在 `OrganizationIdentityCenter` 中取消角色/权限工作台渲染，而不是用 CSS 隐藏。这样契约和 DOM 结构都回到列表优先，避免不可见区域继续影响间距或后续维护判断。
- 对表格列定义移除 AntD `fixed` 配置，而不是覆盖 sticky 阴影样式。固定列是分割线和额外横向滚动体验的根因；桌面列能放下时不应依赖 sticky 布局。
- 保留统一列表壳和各页面自己的列定义、查询回调、分页、权限判断。这样能复用公共密度，同时不扩大到后端接口或权限模型。
- 用聚焦 Jest、typecheck、build 和浏览器 DOM 检查验证行为。该变更主要是前端 UI 布局，不需要数据库或后端接口迁移。

## Risks / Trade-offs

- 角色/权限页移除顶部工作台后，少量跨页面跳转入口不再重复展示。缓解方式：这些入口仍由左侧菜单和既有路由覆盖，列表页保留对象管理主操作。
- 取消固定列后，窄屏或极小容器下操作列可能需要通过表格横向滚动查看。缓解方式：规范允许窄屏使用表格内部横向滚动兜底，桌面优先降低视觉噪声。
- 当前浏览器验证仍能看到项目既有 React warning。缓解方式：记录为既有风险，不把它写成本 change 的验收结论。
