## Why

企业微信同步和飞书同步页面目前进入后会先落到当前账号组织，管理员需要重新选择真实同步组织后才会看到配置和同步记录，容易误判为未配置。

同一个 Admin 业务组织同时配置企业微信、飞书或后续其他通讯录来源时，两套同步都可能写入本地用户、部门关系和禁用状态，虽然映射表按来源隔离，但共享身份资产仍存在覆盖和误禁用风险。

## What Changes

- 企业微信同步和飞书同步页面进入时自动恢复该 Provider 的已配置或最近使用同步组织，并立即加载对应配置、诊断和同步记录。
- 同一个 Admin 业务组织只允许一个通讯录主数据源处于已配置/占用状态；企业微信、飞书和后续钉钉等来源不能复用同一组织。
- 当同一组织已有另一种 Provider 配置时，当前 Provider 页面只允许查看配置和记录，不允许保存草稿、启用或正式同步。
- 保存启用配置、启动手动同步和定时同步执行前均做后端互斥校验，避免绕过前端。
- 前端在另一种 Provider 已配置/占用时展示冲突提示，并禁用当前页的保存、启用同步和正式同步入口。
- 前端组织下拉过滤已被其他通讯录来源占用的组织；当前已选中的冲突组织仍保留显示，便于管理员理解只读原因。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `wecom-organization-sync`: 增加默认同步组织恢复和与其他通讯录同步源互斥的要求。
- `feishu-organization-sync`: 增加默认同步组织恢复和与其他通讯录同步源互斥的要求。
- `organization-sync-scheduler`: 增加定时同步执行前校验单一已配置通讯录源的要求。

## Impact

- 后端：企业微信/飞书组织同步配置服务、同步启动接口、调度执行入口。
- 前端：企业微信同步页、飞书同步页和对应 backend API 封装。
- OpenSpec：更新企业微信同步、飞书同步和组织同步调度能力规格。
- 验证：新增/更新 Go 聚焦测试、前端 Jest 测试，运行 OpenSpec strict 校验和 TypeScript 检查。
