## Context

当前身份控制台壳层已经具备工作区标签、侧栏和多页导航，但页面正文滚动边界仍然不稳定。部分长页面在桌面端会让整个文档一起滚动，导致标签区和页头离开视口；与此同时，总览页、控制台页和工具页各自维护顶部结构和间距，样式逐渐分叉，复用成本升高。

这次改动已经集中落在 `ManagementPage`、身份控制台共享布局、总览页、`ServerStorePage` 和通用样式层，属于明确的跨页面壳层治理，适合通过单独的 OpenSpec change 固化约束。

## Goals / Non-Goals

**Goals:**

- 建立共享页面壳，统一 `header/body` 分区和正文内部滚动职责。
- 让桌面端工作区标签、页面页头和正文滚动边界更稳定，长页面不再优先滚动整个文档。
- 收紧总览页头与右侧状态区密度，减少不必要的视觉噪声。
- 让总览页和工具页在不改业务流程的前提下共享一套基础页头节奏和起始留白。

**Non-Goals:**

- 不改动导航 IA、菜单命名、业务字段、接口契约或后端数据结构。
- 不要求一次性迁移所有历史页面；本 change 只覆盖当前已经接入的共享壳页面和桌面内容区滚动边界。
- 不重做每个页面的业务级表格、筛选或抽屉交互，仅收敛共用壳层。

## Decisions

### 1. 抽取共享 `PageScrollShell`，而不是让每个页面单独写 sticky/header 样式

- 决策：新增一个只负责 `header/body` 结构的轻量共享组件，由页面传入 header 和 children，自身不绑定业务文案或具体工具栏。
- 原因：当前分歧主要来自滚动边界和基础间距，而不是业务结构差异。共享壳能把“页头固定、正文滚动”的规则沉到一个位置，避免后续每个页面再各写一套 flex/overflow 组合。
- 备选方案：在各页面分别用 `position: sticky` 或局部容器样式修补。未采用，因为会继续复制样式，并且难以保证旧 Card 页和新控制台页的行为一致。

### 2. 在 `ManagementPage` 统一内容区滚动，而不是要求每个路由自己处理外层滚动

- 决策：为 `renderRouter()` 结果增加统一的 route scroll 容器，区分“无外层 Card 页面”和“旧 Card 页面”两条渲染分支，但都纳入同一个桌面滚动边界。
- 原因：工作区标签与内容区的边界是壳层职责，放在路由页各自处理会导致统一性很差，也无法约束 legacy Card 页。
- 备选方案：只修身份控制台页面，不动 `ManagementPage`。未采用，因为这会让旧页面继续整页滚动，标签固定问题仍然是壳层级缺陷。

### 3. 把密度收紧做成共享页组件的可选能力，而不是全局一刀切压缩

- 决策：让 `EnterpriseIdentityConsolePage` 支持 `density="compact"`，仅在总览等明确需要降噪的页面启用，同时允许 `eyebrow` 和 `description` 为可选。
- 原因：当前已有部分页面经过单独调优，直接全局收紧容易破坏已经稳定的表格、工具栏和多按钮布局。可选密度更利于渐进迁移。
- 备选方案：统一缩小所有控制台页头 padding/font-size。未采用，因为影响面过大，且不符合用户要求的“不要轻易改公共列表壳已经调好的样式配置”。

### 4. 先把 `ServerStorePage` 接入共享壳，作为工具页样例

- 决策：工具页不强行改成与总览相同的业务结构，但接入相同的页头/正文滚动壳和基础间距。
- 原因：这类页面后续会持续增加，先抽出共用壳比继续保留单页样式更容易扩展，也能验证共享壳不只适用于总览页。
- 备选方案：只治理总览页，工具页继续独立。未采用，因为那会保留明显的样式断层，失去这次 change 的复用价值。

## Risks / Trade-offs

- [嵌套滚动处理不当] -> 通过共享壳统一 `flex/min-height/overflow` 组合，并补充 shell 级测试，避免出现内容被裁切或无法滚动。
- [移动端出现双重纵向滚动] -> 在窄屏断点下让共享壳回退为自然流或单一可用滚动路径，不把桌面滚动策略硬搬到移动端。
- [总览密度压得过紧影响可读性] -> 只对总览启用 `compact`，并保留页面级 class 做局部微调，不全局收紧所有页面。
- [仍有历史页面未迁移] -> 明确这是渐进迁移 change，先固化壳层契约和样例页面，后续页面再按同一模式补齐。

## Migration Plan

1. 保持后端与接口不变，只发布前端壳层与样式改动。
2. 本地 UI 验证优先只启动前端 dev server，并代理到已确认可用的 60 测试后台。
3. 先验证桌面端长页面滚动边界，再验证窄屏下没有新增双重滚动或页面级横向溢出。
4. 如需回滚，可单独撤回共享壳接入和样式层改动，不涉及数据迁移。
