## Context

`PermissionEditPage.tsx` 是 TSX legacy class component，当前字段包括组织、名称、显示名称、描述、模型、授权用户/群组/角色/域、资源类型、资源、动作、效果、启用状态、提交人、审批人、审批时间和状态。页面仍使用旧 Card title 保存按钮、正文底部重复按钮和全宽单列表单，和组织、群组、角色编辑页已形成的编辑壳不一致。

权限页字段量大于角色页，但不是组织页那种多配置域页面。权限的核心流程可以归纳为“谁可以访问什么，以及审批状态”，因此顶层 tabs 不宜拆到 4 个；tab 内区块标题足以承载细分组。

## Goals / Non-Goals

**Goals:**

- 让权限编辑页使用和组织/群组/角色一致的编辑壳：顶部返回路径、未保存状态、正文滚动和固定底部操作栏。
- 使用两个顶层 tabs：`基础` 与 `规则`。
- 在 `基础` tab 内用区块标题分 `基础信息`、`授权主体`。
- 在 `规则` tab 内用区块标题分 `资源动作`、`审批信息`。
- 为 `名称`、`显示名称` 增加必填标识和保存前校验。
- 保留现有权限保存、保存并返回、新增取消删除临时权限、保存失败回滚权限名、普通用户修改限制和 `/permissions` 返回语义。

**Non-Goals:**

- 不修改权限模型、Casbin 行为、资源/动作枚举、审批权限规则或后端 API。
- 不修改权限列表页。
- 不把权限页拆成 4 个顶层 tabs。
- 不改造角色、群组、用户等其它编辑页的完整正文布局；本轮只补齐与权限页迁移直接相关的公共编辑页结构与选择项展示能力。

## Decisions

### 双 Tabs 而不是四 Tabs

权限页采用两个顶层 tabs：

- `基础`：包含基础信息和授权主体。管理员先确认权限对象和适用主体。
- `规则`：包含资源动作和审批信息。管理员再确认授权规则和审批状态。

备选方案是 4 tabs：基础信息、授权主体、资源动作、审批。它的缺点是 tab 数量接近组织页，但每个 tab 内字段不多，会增加跳转成本，也和“tab 内已有分类标题”的迁移规则冲突。双 tabs 更符合权限页的信息密度。

### 复用编辑壳但保持页面作用域

权限页应接入和大型编辑页一致的头部、tabs、滚动正文和底部操作栏。样式应挂在 `.permission-edit-page` 下，保留 `permission-edit-page` 和 `permission-edit-card` scoped class，便于测试和后续局部修复。

`/permissions/:organizationName/:permissionName` 需要纳入 `ManagementPage.isWithoutCard()` 的 large edit page cardless pattern，否则外层 `content-warp-card` 会导致底部操作栏无法固定在编辑区域底部。

权限页迁移暴露了 tabs、区块标题、表单行和必填标识在各编辑页重复实现的问题。本轮将这些结构沉到 `LargeEditShell` 同目录公共导出，并保留页面级 class 前缀，避免后续继续在每个编辑页复制同一套标题和表单栅格样式。角色页本轮不整体切换正文组件，只同步组织下拉的展示样式，降低扩散风险。

### 技术标识类下拉展示

组织、模型这类字段最终保存内部标识，但管理员需要优先看到可读显示名。权限页的组织和模型下拉、角色页的组织下拉统一采用两行选项：首行显示 `displayName`，次行显示内部标识；选中框只显示 `displayName`。搜索同时匹配显示名和内部标识，保存 payload 仍保持原内部值。

### 保存、取消与校验

权限页新增 `dirty`、`submitting`、`activeTabKey` 和字段错误状态。任意字段变更标记 dirty；保存成功清除 dirty；返回和取消触发 dirty 确认。

保存前先校验：

- `name`、`displayName` 非空，并展示字段错误。
- 现有业务校验保持不变：用户和角色不能同时为空、资源不能为空、动作不能为空、普通用户只能修改自己提交的权限。

校验失败如果错误字段不在当前 tab，应切换到对应 tab。业务校验按字段所属 tab 切换：授权主体错误切到 `基础`，资源/动作错误切到 `规则`。

## Risks / Trade-offs

- [Risk] 权限页字段较多，双 tabs 可能仍需要滚动。
  - Mitigation: tab 内使用区块标题和两列表单网格，保留正文独立滚动和固定底部操作栏。
- [Risk] 复用 large edit 样式可能影响已有角色/群组页。
  - Mitigation: 新增样式挂在 `.permission-edit-page` 作用域下，避免裸写 AntD selector。
- [Risk] 旧权限页测试和角色页测试在同一个文件中，迁移可能误伤角色/权限共享断言。
  - Mitigation: 更新 `RolePermissionEditPages.test.tsx` 时保留角色页和旧权限行为覆盖，新增权限壳、tabs、校验、dirty 确认断言。
