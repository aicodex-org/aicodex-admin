## Context

`SyncerEditPage.tsx` 已完成 TypeScript 迁移，但仍由一个带操作标题的 `Card`、约二十组 legacy `Row/Col` 字段和页面末尾第二组按钮组成。页面同时承载多种 Syncer 类型的动态连接字段、连接测试、表格列映射、错误文本与启用状态，直接重写全部字段结构会扩大契约回归风险。

当前大型编辑页已经沉淀 `LargeEditShell`、公共 legacy row 样式、tabs 和统一底部按钮。初版 RC 将 Syncer 作为单页配置型编辑页，但完整滚动截图表明三个配置域已经足够稳定，继续纵向堆叠会让空表格和错误信息放大页面长度；最终方案改为三个页内 tabs，头部、滚动区和底部操作仍复用同一壳。

## Goals / Non-Goals

**Goals:**

- 让 Syncer 新增/编辑页复用共享大型编辑页壳，并只保留一个动作栏。
- 使用公共正文和 legacy row 边界统一标签宽度、控件伸缩、表格容器、暗色和窄屏表现。
- 将基本信息、连接配置、映射与状态拆成三个 tabs，并在当前 tab 内保留公共分类标题，减少长页滚动的同时维持正文层级，不改变动态字段出现条件和保存数据。
- 让组织选项同时呈现显示名称与标识，并支持按两者搜索，复用既有大型编辑页选项样式。
- 用聚焦测试保护壳结构、动作语义、动态字段和保存 payload。

**Non-Goals:**

- 不重写所有 legacy `Row/Col` 为 `LargeEditFieldRow`。
- 不新增 Syncer API，不改变 payload、类型切换默认值、连接测试、既有记录删除、跳转、权限或真实同步行为；新增态仅调整为保存时创建，取消不写入后端。
- 不主动执行真实数据库连接测试、外部目录同步或环境数据写入。
- 不在本次引入新的脏状态、离开确认、字段校验体系或共享业务组件。

## Decisions

1. **使用三个 tabs 的 `LargeEditShell`。**
   基本信息、连接配置、映射与状态已经形成稳定配置域。类型选择仍位于基本信息 tab，切换后直接更新同一组件状态中的动态字段；tabs 只控制展示，不拆分表单状态或保存 payload。当前 tab 写入 URL hash，刷新后恢复。

2. **保留业务字段 JSX，增加公共 legacy 正文边界。**
   `admin-large-edit-form-content` 已为 legacy `Row/Col` 提供稳定 label/content 列和局部表格约束。相较一次性迁移全部字段，这能以更小改动获得一致密度，同时避免影响动态类型逻辑。

3. **三个 tabs 继续复用同一 legacy 正文边界。**
   基本信息承载组织、名称和类型；连接配置承载数据库/目录连接及测试；映射与状态承载表格列、工作单位、头像、周期、错误文本和开关。每个当前 tab 继续显示带左侧标记的公共分类标题，tab 面板只改变视觉分组，不改变字段 handler、条件和提交数据。

4. **共享壳底部动作是唯一保存入口。**
   取消、保存、保存并返回均由 `LargeEditShell.actions` 渲染。编辑态和添加态取消都返回 Syncer 列表；添加态只在保存时调用新增接口，保存方法和参数保持不变。

5. **组织下拉复用大型编辑页双层选项表现。**
   选项主行显示 `displayName`（为空时回退 `name`），副行显示标识 `name`，提交值仍为 `name`。搜索同时匹配显示名称和标识，不引入新的组织选择组件或请求。

6. **测试聚焦可观察契约，不追求机械行覆盖。**
   组件测试覆盖加载后壳结构、唯一动作栏、代表性类型切换、连接测试不被自动触发、保存 payload 和添加态取消。覆盖率用于发现新增壳辅助逻辑的空白，不通过执行真实连接或遍历全部历史列 fixture 拉高数字。

## Risks / Trade-offs

- [Risk] legacy 字段仍有大量内联 margin。→ 页面私有 LESS 只覆盖公共正文边界下的直接行间距，不做全文件机械 JSX 重写。
- [Risk] 不同 Syncer 类型的字段高度差异大。→ 自动化覆盖数据库类型和一个外部目录类型，浏览器基于 60 测试后台逐个检查可访问的现有类型，但不触发连接测试。
- [Risk] 类型切换会改变非当前 tab 的字段。→ tabs 共用同一 `syncer` 状态对象，不卸载或复制业务数据，测试约束切换类型后字段默认值和保存 payload 不变。
- [Risk] 表格列映射可能需要局部横向滚动。→ 允许表格组件内部滚动，浏览器验证页面根节点无横向 overflow。
- [Risk] URL hash 可能包含未知 tab。→ 未知或空 hash 回退到基本信息，不影响路由和保存。

## Migration Plan

1. 完成并严格校验 OpenSpec artifacts。
2. 先写失败的 Syncer 编辑页壳与行为测试。
3. 接入共享壳、三个 tabs 和组织选项表现，新增最小 `syncer-edit.less`。
4. 运行聚焦测试、覆盖率、增量 TypeScript gate、typecheck 和 build。
5. 启动本地前端代理 60 测试后台，完成桌面/窄屏、浅色/暗色和 overflow smoke。
6. 提交并推送 RC 工作分支；若需回滚，恢复页面组件和样式导入即可，后端与数据无需迁移。
