## Context

`InvitationEditPage.tsx` 已完成 TypeScript 迁移，但仍使用旧式 `Card` title 操作区、`Row` / `Col` 字段行和正文末尾重复按钮。仓库现有 `LargeEditShell` 已统一头部、路径、滚动正文和固定底部操作栏，`LargeEditSection` / `LargeEditFieldRow` 已统一分区与字段布局；Role、Permission、Provider 等页面已经验证这套边界。

本次是纯前端结构改造。邀请码数据仍由现有 backend client 和 60 测试后台提供，前端只展示和编辑当前记录，不成为任何数据或同步事实的 owner。

## Goals / Non-Goals

**Goals:**

- 让邀请码编辑页复用公共编辑壳，并保持桌面与窄屏布局稳定。
- 让所有现有字段按可扫描的业务语义进入公共 section/field row。
- 让主要操作只出现在固定底部栏，滚动正文时保持可达。
- 保持原有加载、字段更新、复制、发送、保存、退出语义和 payload；新增邀请码改为前端草稿，取消或返回不写入。
- 让组织选择使用可读显示名，并在保存前校验邀请码名称与非空邮箱格式。
- 通过聚焦测试、TypeScript/build 检查和只读浏览器逐段滚动截图验证结构。

**Non-Goals:**

- 不新增未保存修改确认、权限规则或业务字段。
- 不改变邀请码 API、路由、保存 payload、默认应用判断、复制链接格式或发送邀请流程。
- 不触发真实保存、发送、删除、外部同步或数据库写入来完成浏览器验收。
- 不重构 backend client、ManagementPage、其它编辑页或全局设计系统。

## Decisions

### 1. 直接复用公共编辑壳，不创建邀请码专用壳

页面根节点使用 `identity-object-edit-page invitation-edit-page`，内部 Card 只承载一个 `LargeEditShell`。头部显示返回按钮、`组织账号 / 邀请码 /` 路径和当前对象标题；正文由 shell 内部独立滚动，底部只保留一组动作。

备选方案是复制 Role 页面 DOM 或保留 Card title，仅补 CSS sticky。前者会重复公共结构，后者无法消除重复操作和双壳问题，因此不采用。

### 2. 按邀请码真实字段语义划分四个 section

- 基础信息：组织、名称、显示名称。
- 邀请配置：邀请码、默认邀请码、复制注册链接、发送邀请、配额、已使用数。
- 注册目标：应用、注册群组。
- 注册信息：用户名、邮箱、手机号、状态。

每个字段使用 `LargeEditFieldRow`，宽操作区按需使用 `wide`。不把同步器领域的“源配置 / 目标配置 / 字段映射”文案硬套到邀请码模型。

### 3. 保持新增草稿语义，并补充本地可发现的格式错误

固定底栏保留保存、保存并退出和取消；公共头部返回入口直接回到 `/invitations`。新增模式的默认记录只随路由 state 传递，页面加载时不读取该不存在的详情；只有保存或保存并返回才调用 `addInvitation`，创建成功后切换为编辑模式。取消和返回不调用创建、更新或删除接口。本次不增加 dirty state 或离开确认。

组织下拉以 `displayName || name` 展示，但选项值和保存 payload 始终使用稳定的组织技术名 `name`。保存前阻断空名称、非 ASCII 技术 ID（仅允许字母、数字、下划线和连字符），以及非空但不符合 `Setting.isValidEmail` 的邮箱；错误通过公共 field row 的本地化字段提示展示，不调用保存 API。

### 4. 测试先验证结构，再做最小实现

先扩展 `InvitationEditPage.test.tsx`，要求公共 shell、路径、四个 section、公共字段行、唯一动作栏和无旧重复按钮；确认测试因页面仍为旧结构而失败后，再修改生产代码。现有保存、复制、发送、删除与错误分支测试继续作为行为兼容证据。

### 5. RC 验收只做只读观察

完成自动化验证后，通过仓库脚本启动本地前端代理到 60 测试后台。浏览器只打开目标路由、逐段滚动、检查布局/overflow/console 并截图，不点击保存、保存并退出、发送、取消新增、删除或其它会产生写入的控件。

### 6. 页面内操作和底栏动作对齐公共编辑页

邀请码正文中的发送动作使用 AntD 紧凑按钮尺寸，避免普通表单按钮在宽字段中显得过重。固定底栏在新增和编辑模式下均按“取消 / 保存 / 保存并返回”排列；新增模式取消和顶部返回只丢弃路由草稿，编辑模式取消只返回邀请码列表。该修订不新增 dirty state 或离开确认，也不改变保存、发送 API 与 payload。

## Risks / Trade-offs

- [新增返回入口未提供 dirty 确认] → 本次明确不扩展行为保护；返回入口与用户确认的兼容边界一致，后续如需 dirty guard 单独立项。
- [旧字段数量较多导致窄屏溢出] → 使用公共 field row 网格和 scoped class，并在 1280px 与窄屏视口检查页面级 overflow。
- [测试 mock 数据与 60 数据形态不同] → 单测只证明前端结构和既有 handler；浏览器 smoke 单独记录为 60 测试后台的只读 UI 证据，不夸大为保存链路验收。
- [发送邀请 Modal 本身是写操作入口] → 可验证按钮与 Modal 结构的自动化测试；RC 浏览器不点击该入口。
- [前端校验与后端校验口径不同] → 仅拦截项目已有规则可明确判断的名称字符和邮箱格式，后端仍保留唯一性与其它业务规则的最终裁决。
