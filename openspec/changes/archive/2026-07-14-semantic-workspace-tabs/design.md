## Context

Admin Shell 已从企业导航派生 `WorkspaceRouteItem`，并用完整 path 区分已打开的标签。因此同一列表中打开多个对象编辑页不会互相覆盖，但标签文字仍沿用列表菜单名，导致标签栏出现多个相同名称。群组编辑页已有详情数据加载后的标题更新事件，可作为应用编辑页的复用边界。

## Goals / Non-Goals

**Goals:**

- 列表页继续使用现有导航名称。
- 同一列表 route 只保留一个标签；对象编辑页和新增草稿页均按完整编辑 route 独立打开。
- 已声明的对象编辑路由使用 `编辑：对象标识` 形式的初始标题；对象标识来自最后一个 URL path segment 并进行解码。
- 只在声明的详情深度应用编辑标题；购买、支付、结果等动作子页继续使用其所属路由标题。
- 应用、组织、证书及具有稳定详情加载链路的低风险对象编辑页获取详情后将标签更新为对应的编辑语义和显示名称，显示名称为空时回退对象标识。
- 桌面标签、移动当前页和更多菜单继续复用同一个 `WorkspaceTabItem.label`。

**Non-Goals:**

- 不修改侧边栏菜单、路由 path、权限过滤、sessionStorage schema 或页面关闭/滚动交互。
- 不把同一资源类型的新增页强制合并为单一标签：现有新增流程会先创建具有唯一标识的服务端草稿，合并标签会让后续草稿失去可见且可返回的编辑入口。
- 不在同一批次机械接入具有多源异步数据、草稿状态或嵌套显示名称的复杂编辑页；它们必须在明确对象 owner 和保存后路径后单独接入。
- 不改动业务对象、后端 API 或编辑表单字段。

## Decisions

### 详情标题由导航元数据声明

在导航叶子项到 `WorkspaceRouteItem` 的派生过程中增加可选的编辑标题和详情 path depth。`workspaceTabState` 仍是标签标题的唯一派生点，避免在 `WorkspaceTabs`、路由页和菜单中各自解析 URL。

选择显式深度而非“所有深层 path 都是编辑页”的推断：同一资源下存在 `/products/:id/buy`、`/orders/:id/pay`、`/payments/:id/result` 等动作页面，盲目按最后一段命名会把动作误认为对象。

### 列表复用、对象与草稿独立

列表页没有对象级上下文，按导航 route 去重即可。对象编辑和新增流程则使用完整编辑 path 作为标签身份；已有实现中新增操作通常先创建服务端草稿并跳转到该 path，因此即使处于 `add` 模式也必须保留独立标签。这样管理员可以并行处理多个草稿，不会因新打开同类草稿而覆盖前一个未保存表单。

购买、支付、结果等动作页继续由其所属导航 route 呈现，不把动作子路径当作独立对象编辑标签。

### 初始路由标识与业务显示名称分阶段更新

打开对象编辑页时立即使用 URL 中的对象标识，保证刷新、直达链接和详情请求失败时仍可辨识。应用详情加载成功后通过既有 `WORKSPACE_TAB_LABEL_UPDATE_EVENT` 仅更新已打开标签的 `label`；路径、顺序和持久化格式保持不变。

工作页标签区分路由默认标题和详情标题来源。普通路由切换时更新 route metadata，但不得用默认标题覆盖已经加载的详情标题；浏览器会话恢复仍只依据 path 重新派生默认标题，不把业务标题写入 sessionStorage。

选择事件更新而不是让 Shell 请求业务 API：Shell 不应拥有应用详情数据或重复业务加载逻辑，编辑页已是数据 owner。

### 显示名称分批接入

只要编辑对象自身具有非空 `displayName`，它就是工作页标签和页内主标题的首选标识；技术名称仅用于详情尚未加载、显示名称为空或加载失败时回退。每个编辑页在成功写入详情状态后发布事件，并仅在对象自身 `displayName` 变更时再次发布。

低风险页面按独立代码文件分批接入。草稿、保存后改名路由、多源异步加载或嵌套 `displayName` 页面不得套用机械修改，避免把关联对象名称误作当前编辑对象名称。

### 不新增标签栏展示层

标签文字直接写入现有 `WorkspaceTabItem.label`。桌面标签、移动端当前页和“更多工作页面”菜单天然一致，且保留现有截断、title 和关闭 aria-label 行为。

## Risks / Trade-offs

- [尚未接入详情事件的编辑页显示技术标识] → 所有声明的编辑路由先以 path 标识区分；后续仅在对应页面已有稳定详情加载点时再增加显示名称更新。
- [新增编辑路由遗漏元数据] → 聚焦测试覆盖已声明的编辑项、列表页和动作子路由，导航 metadata 集中维护。
- [把新增草稿合并到同一标签导致草稿不可见] → 新增草稿继续使用其完整编辑 path；仅列表页按资源 route 复用。
- [路由刷新覆盖详情标题] → 状态测试覆盖详情标题更新后切换列表和其它编辑页的保持行为。
- [显示名称含长文本] → 沿用标签现有宽度、截断与完整 title，不扩大标签或页面宽度。
- [嵌套字段或关联对象的显示名称误更新标签] → 仅允许对象顶层 `displayName` 触发事件；复杂页面单独审计和测试。

## Migration Plan

前端部署后，新打开或刷新恢复的标签将按最新导航元数据重新派生标题；sessionStorage 只保存 path，无需迁移。回滚时移除详情元数据与应用标题更新即可恢复菜单名称标题，不影响已保存的 path。
