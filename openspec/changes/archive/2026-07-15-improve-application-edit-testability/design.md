## Context

`ApplicationEditPage.tsx` 是一个 2,103 行的历史 class component。它同时拥有详情加载、字段规范化、提交校验、保存副作用和八个配置 Tab 的 JSX。当前 4 个直接引用该页面的测试套件共 67 个用例，覆盖率统计为 Lines 48.41%、Statements 47.72%、Functions 35.67%、Branches 46.13%。

应用编辑页承载 Provider、SAML、认证策略及反向代理配置，直接依赖真实外部认证或部署环境的分支不适合用浏览器端 mock 伪造。此次只治理前端内部可确定的编辑和保存语义，不更改后端契约或真实认证链路。

## Goals / Non-Goals

**Goals:**

- 保持应用详情加载、字段编辑、路由、Tab、错误提示、保存 payload 和跳转语义兼容。
- 将具有独立职责的纯规则和 Tab 内容分批提取为 TypeScript 模块或组件，令复杂逻辑可在不构造整个页面的情况下被验证。
- 为关键用户路径建立真实行为断言，并使 `ApplicationEditPage.tsx` 与本 change 新增的生产模块在完整相关测试集合下达到不低于 85% 的行覆盖率。
- 覆盖率统计包含所有直接引用应用编辑页或拆分模块的现有与新增测试，不通过排除文件、只测 mock 调用次数或移动未测试代码规避门槛。

**Non-Goals:**

- 不修改应用后端 API、Provider/OIDC/SAML 协议、认证回调、数据模型、权限或部署配置。
- 不重做应用编辑页视觉设计，不统一替换所有历史 class component，也不在本 change 迁移无关页面。
- 不用真实账号、真实 Provider、敏感配置或生产/类生产数据作为单测 fixture。

## Decisions

### 先提取稳定职责，再收缩页面协调层

优先从纯字段规范化、校验、保存 payload 组装和内容相对独立的 Tab 提取模块；页面本体只保留路由参数、异步调用编排、状态协调和已存在的布局入口。相比直接为 2,103 行文件堆叠 DOM 测试，这能让测试围绕业务规则和用户结果而不是内部 JSX 结构。

不选择一次性改写为 hooks 或全量重构：这会同时改变生命周期、异步状态和大量表单行为，风险远高于本 change 的测试性目标。

### 以可观察配置语义设计测试

测试优先验证详情默认值、字段规范化、必填与自定义 scope 错误定位、重复提交保护、Provider/SAML/安全/反向代理配置切换，以及最终保存 payload 与成功跳转。后端 wrapper 保持为窄 mock 边界；不以断言私有 helper 的调用次数替代配置结果断言。

### 覆盖率以完整关联回归集为准

覆盖率命令必须同时包含 `ApplicationEditPage.test.tsx`、`ApplicationEditPageUiCustomization.test.tsx`、`LargeEditFormLayout.test.ts`、引用该页面的壳层测试，以及新增拆分模块测试。若拆分后仍有其它直接引用页面的测试，也必须纳入。目标针对 `ApplicationEditPage.tsx` 和本 change 新增/实质修改的生产模块分别达到 85% 行覆盖率。

不选择仅统计新 helper：页面协调层仍是用户工作流的一部分，只有其自身和拆分模块均受回归保护，才算完成治理。

## Risks / Trade-offs

- [拆分时遗漏旧状态或回调依赖] → 每批仅抽取一个稳定职责，先以现有测试锁定行为，再增加保存 payload、错误定位和浏览器 smoke 验证。
- [为覆盖率触碰高风险认证语义] → 保持 Provider/OIDC/SAML API 和真实登录链路不变，只测试前端显示、字段处理和请求参数。
- [测试运行时间增加] → 复用现有 mock 和 fixture，测试以独立模块单测为主，页面级测试只覆盖跨模块用户路径。
- [完整页面仍无法达到 85%] → 不以例外或统计规避收口；记录剩余未覆盖分支及其拆分计划，继续下一批直到满足门槛或由用户明确调整范围。

## Migration Plan

1. 先补齐基线和行为测试，再逐批提取模块并保持无后缀 import 兼容。
2. 每批运行关联 Jest、类型检查和覆盖率；出现 payload、路由或错误提示回归即回退该批实现。
3. 前端部署后使用本地预览代理测试后台验证应用编辑页的加载、Tab 切换和无保存浏览流程；不修改测试后台数据。
4. 回滚只需恢复本次新增模块引用，页面既有 API 与持久化格式不变。
